# برومبت بناء المنصة التعليمية (المدرسة الإلكترونية)

> انسخ كل ما بعد هذا السطر والصقه في Claude Code بعد فتحه داخل المجلد `e:\school2028\sms`

---

أنت مهندس .NET كبير ومعماري أنظمة. مهمتك بناء **"المنصة التعليمية – المدرسة الإلكترونية"** كامتداد متكامل لنظام إدارة المدرسة (SMS) الموجود في المجلد الحالي. النظام مبني بـ **ASP.NET Core 5.0 + C# + SQL Server 2017**. المنصة تتيح للمعلم والطالب وولي الأمر التفاعل التعليمي خارج أوقات الدوام: الواجبات، أوراق العمل، الاختبارات الإلكترونية، الأنشطة الصفية، المحتوى التعليمي، التواصل، والتقارير.

اعمل بأسلوب تكراري منضبط: استكشف، خطّط، احصل على موافقتي، نفّذ مرحلة، اختبر، لخّص، توقّف. لا تقفز لمرحلة قبل تأكيدي.

## المرحلة 0 – الاستكشاف والتخطيط (ممنوع كتابة أي كود قبل إتمامها)

### 0.1 فحص المشروع
1. افحص ملفات `.sln` و`.csproj`: أكّد إصدار `net5.0`، الحزم المستخدمة وإصداراتها، وعدد المشاريع وأدوارها (Web / Core / Data / Services / Tests).
2. حدد نوع الواجهة: MVC أم Razor Pages أم Blazor أم Web API + واجهة منفصلة. حدد مكتبات الواجهة (Bootstrap، jQuery، DataTables، Select2، Kendo… إلخ) وطريقة التعريب والـ RTL الحالية.
3. حدد طبقة الوصول للبيانات: EF Core (أي إصدار؟ Code First أم Database First؟ هل توجد Migrations؟) أم Dapper أم ADO.NET أم Stored Procedures.
4. حدد المصادقة والصلاحيات: ASP.NET Core Identity أم نظام مخصص، Cookie أم JWT، Roles أم Claims أم Policies، وأين تُعرَّف.
5. حدد الأنماط المستخدمة: Repository / Unit of Work / Services / CQRS / ViewModels / AutoMapper / FluentValidation / DataAnnotations / Logging (Serilog/NLog) / DI.
6. حدد كيف تُدار: العام الدراسي، الفصل الدراسي، الصفوف، الشُعب، المواد، توزيع المعلمين على المواد والشعب، الطلبة وتسجيلهم في الشعب، أولياء الأمور، الحضور، الدرجات، الجدول الدراسي.
7. ابحث عن أي بنية تحتية موجودة يمكن إعادة استخدامها: رفع ملفات، إرسال بريد/SMS، إشعارات، تصدير Excel/PDF، طباعة، إعدادات عامة، سجل تدقيق (Audit).
8. إذا وجدت سكربتات قاعدة بيانات أو نسخة احتياطية في `docs/db/` أو أي مكان، اقرأها لفهم الـ Schema. لا تفترض بنية الجداول دون دليل.

### 0.2 المخرجات المطلوبة قبل الموافقة
أنشئ المجلد `docs/eschool/` وضع فيه:
- `01-EXPLORATION.md`: ملخص كل ما سبق، مع جدول "موجود / سيُعاد استخدامه / ناقص ويجب إضافته".

## المبادئ الإلزامية طوال المشروع

### التكامل مع النظام الحالي
- **لا تنشئ نظام مستخدمين أو صفوف أو مواد موازياً.** ابنِ فوق الكيانات الموجودة عبر مفاتيح خارجية. أضف فقط ما هو ناقص (مثل دور الطالب أو ولي الأمر إن لم يكن موجوداً، أو جدول ربط الطالب بولي الأمر).
- الأدوار: `Admin`، `Teacher`، `Student`، `Parent`. إن كانت مسمّاة بشكل مختلف في النظام، استخدم المسميات الموجودة.
- التزم بنفس بنية الطبقات، أسلوب التسمية، الـ Patterns، مكتبات الواجهة، وطريقة التعريب المستخدمة في المشروع. المنصة يجب أن تبدو جزءاً أصيلاً من النظام لا إضافة غريبة.
- لا تُحدّث إصدار .NET أو أي حزمة رئيسية دون إذن صريح مني.

### قاعدة البيانات (SQL Server 2017)
- الجداول الجديدة تحت schema باسم `eschool`.
- كل تغيير عبر **EF Core Migrations** قابلة للتراجع (`Up`/`Down`). إذا كان المشروع لا يستخدم EF Migrations، فاستخدم سكربتات SQL مرقّمة في `db/eschool/` مع سكربت تراجع لكل منها.
- التزم بـ Compatibility Level 140: لا تستخدم `GREATEST/LEAST`، ولا تحسينات JSON الخاصة بـ 2022، ولا `DATETRUNC`. استخدم `STRING_AGG` و`OPENJSON` بحذر وبعد التأكد من التوافق.
- فهرسة مناسبة لكل الأعمدة المستخدمة في التصفية والربط (StudentId، SectionId، SubjectId، DueDate، CreatedAt…).
- أعمدة قياسية في كل جدول: `Id`، `CreatedAt`، `CreatedBy`، `UpdatedAt`، `UpdatedBy`، `IsDeleted` (Soft Delete مع Global Query Filter).
- استخدم `datetime2` وخزّن التواريخ بتوقيت UTC، واعرضها بالتوقيت المحلي.

### الأمن والصلاحيات
- Authorization عبر **Policies + Resource-based Authorization Handlers**، وليس عبر التحقق من الدور فقط.
- قواعد الملكية تُفرض في الخادم عند **كل** قراءة وكتابة:
  - المعلم: فقط الشعب والمواد المسندة إليه في العام/الفصل الحالي.
  - الطالب: فقط ما يخص شعبته وما يخصه شخصياً.
  - ولي الأمر: فقط الأبناء المرتبطون به، قراءة فقط باستثناء الرسائل.
  - الإدارة: الكل.
- رفع الملفات: قائمة بيضاء للامتدادات (pdf, docx, xlsx, pptx, jpg, png, mp4)، فحص الحجم (حد قابل للضبط من الإعدادات)، فحص الـ Magic Bytes لا الامتداد فقط، إعادة التسمية بـ GUID، التخزين **خارج** `wwwroot` في مسار من الإعدادات، والتقديم عبر Endpoint يتحقق من الصلاحية قبل الإرسال.
- حماية من CSRF (AntiForgery في كل نموذج)، XSS (ترميز كل مخرجات المستخدم، وتنقية أي HTML مسموح عبر مكتبة موثوقة)، SQL Injection (لا استعلامات نصية مركّبة).
- Rate Limiting على نقاط تسليم الاختبارات والرسائل.
- سجل تدقيق (Audit Log) للعمليات الحساسة: تعديل الدرجات، حذف الواجبات، تغيير نتائج الاختبار، تغيير الصلاحيات.

### الواجهة
- عربية بالكامل، RTL، متجاوبة مع الهاتف (Mobile First)، النصوص في ملفات Resources.
- لوحة رئيسية (Dashboard) لكل دور تعرض الأهم أولاً: المستحق اليوم، الجديد، غير المقروء.
- تغذية راجعة فورية للمستخدم (Toast/Alert) بعد كل عملية، وحالات فارغة واضحة (لا توجد واجبات بعد…).
- إمكانية الوصول: تباين ألوان كافٍ، تسميات للحقول، دعم لوحة المفاتيح.

### جودة الكود
- `async/await` في كامل مسار البيانات، `CancellationToken` في الخدمات.
- ViewModels/DTOs منفصلة عن الكيانات؛ لا تُمرّر الكيانات للواجهة مباشرة.
- التحقق في الخادم دائماً (بالإضافة لأي تحقق في المتصفح).
- معالجة الأخطاء مركزياً مع رسائل عربية مفهومة، والتفاصيل التقنية في الـ Logs فقط.
- اختبارات **xUnit** للمنطق الحساس: الصلاحيات، حساب حالة التسليم، التصحيح الآلي، حساب الدرجات، النوافذ الزمنية للاختبارات.
- بعد كل مرحلة: `dotnet build` بلا تحذيرات جديدة، `dotnet test` ناجح، تحديث `docs/eschool/CHANGELOG.md`، وملخص بخطوات الاختبار اليدوي.

## المراحل الوظيفية (تُنفَّذ بعد موافقتي على الخطة، مرحلة واحدة في كل مرة)

### المرحلة 1 – الأساس
- إضافة الأدوار والسياسات الناقصة وتسجيل الـ Authorization Handlers.
- جدول `eschool.StudentGuardians` لربط الطالب بولي الأمر (مع نوع العلاقة وصلاحية الاطلاع).
- حسابات أولياء الأمور وربطها (استيراد من البيانات الموجودة إن توفرت).
- إعدادات المنصة `eschool.Settings`: الحد الأقصى لحجم الملفات، الامتدادات المسموحة، سياسة التسليم المتأخر، ساعات السماح، تفعيل/تعطيل وحدات.
- نظام إشعارات داخلي: `eschool.Notifications` (المستلم، النوع، العنوان، النص، الرابط، مقروء/غير مقروء)، خدمة إرسال مركزية، عداد في شريط التنقل، صفحة الإشعارات. جهّز واجهة `INotificationChannel` لإضافة البريد/SMS لاحقاً دون تعديل المنطق.
- لوحة رئيسية أولية لكل دور مع التنقل.
- بيانات تجريبية (Seed) لبيئة التطوير فقط.

### المرحلة 2 – الواجبات وأوراق العمل
**الكيانات:** `Assignments`، `AssignmentTargets` (الشعب المستهدفة)، `AssignmentAttachments`، `Submissions`، `SubmissionAttachments`، `Worksheets`، `WorksheetAttachments`.

**المعلم:**
- إنشاء واجب: العنوان، الوصف (محرر نص منسق آمن)، المادة، الشعب المستهدفة (متعدد)، تاريخ ووقت التسليم، الدرجة الكاملة، السماح بالتسليم المتأخر (نعم/لا، وحتى متى، وخصم اختياري)، نوع التسليم المسموح (نص/ملف/كلاهما)، مرفقات، حالة مسودة/منشور.
- تعديل/حذف (حذف منطقي) مع منع حذف واجب له تسليمات إلا للإدارة.
- شاشة التسليمات: جدول بالطلبة وحالة كل منهم (سُلّم في الموعد / متأخر / لم يُسلَّم)، فتح التسليم، وضع الدرجة والتغذية الراجعة، إعادة للتعديل.
- تقييم جماعي سريع (إدخال درجات عدة طلبة في شاشة واحدة).
- مكتبة أوراق عمل: رفع ورقة عمل مرتبطة بمادة وصف، وسوم، إعادة الاستخدام عبر السنوات، تحويل ورقة عمل إلى واجب بنقرة.

**الطالب:**
- قائمة الواجبات مقسمة: مستحقة، قادمة، مُسلَّمة، منتهية. فرز حسب الموعد.
- صفحة الواجب: التفاصيل والمرفقات والعداد التنازلي للموعد.
- التسليم: نص و/أو ملفات، مع تأكيد وتحديث لاحق قبل الموعد، وسجل بمحاولات التسليم.
- عرض الدرجة والتغذية الراجعة بعد التقييم.

**ولي الأمر:** عرض واجبات الأبناء وحالتها والدرجات، قراءة فقط.

**قواعد:** حالة التسليم تُحسب في الخادم بناءً على الموعد والإعدادات. إشعار للطلبة عند نشر واجب، وقبل الموعد بيوم، وعند التقييم؛ وإشعار للمعلم عند التسليم؛ وإشعار لولي الأمر عند التأخر.

### المرحلة 3 – الاختبارات الإلكترونية
**الكيانات:** `QuestionBanks`، `Questions`، `QuestionOptions`، `Exams`، `ExamQuestions`، `ExamTargets`، `ExamAttempts`، `AttemptAnswers`.

**بنك الأسئلة:**
- أنواع الأسئلة: اختيار من متعدد (إجابة واحدة أو أكثر)، صح/خطأ، إكمال الفراغ (إجابات مقبولة متعددة، مع تجاهل الفراغات وحركات التشكيل اختيارياً)، مقالي.
- كل سؤال: المادة، الصف، الوحدة/الدرس، مستوى الصعوبة، الدرجة الافتراضية، صورة اختيارية، شرح الإجابة.
- استيراد أسئلة من Excel بقالب محدد، وتصدير.
- مشاركة الأسئلة بين معلمي المادة نفسها (اختيارياً حسب الإعدادات).

**إنشاء الاختبار:**
- العنوان، المادة، الشعب، نافذة الإتاحة (من – إلى)، المدة بالدقائق، عدد المحاولات المسموحة، ترتيب عشوائي للأسئلة والخيارات، عرض النتيجة (فوراً / بعد انتهاء النافذة / يدوياً)، عرض الإجابات الصحيحة (نعم/لا)، درجة النجاح.
- اختيار الأسئلة يدوياً من البنك أو توليد عشوائي بشروط (عدد من كل صعوبة/وحدة).
- معاينة الاختبار كما يراه الطالب.

**أداء الاختبار (الطالب):**
- لا يبدأ إلا داخل النافذة. عند البدء تُسجَّل محاولة بوقت البداية، والمدة تُحسب في الخادم لا في المتصفح.
- حفظ تلقائي لكل إجابة فور اختيارها (AJAX) حتى لا تضيع عند انقطاع الاتصال.
- عداد زمني، التنقل بين الأسئلة، علامة "للمراجعة".
- عند انتهاء الوقت يُغلق الاختبار تلقائياً ويُسلَّم ما تم حفظه.
- منع فتح المحاولة نفسها من جلستين متزامنتين.

**التصحيح:**
- آلي فوري للموضوعي. يدوي للمقالي بشاشة تصحيح للمعلم مع تغذية راجعة.
- الدرجة النهائية تظهر للطالب حسب سياسة العرض المحددة.
- المعلم يستطيع إعادة فتح محاولة أو منح محاولة إضافية لطالب محدد مع تسجيل ذلك في سجل التدقيق.

**التحليلات:** لكل اختبار: المتوسط، الأعلى، الأدنى، نسبة النجاح، توزيع الدرجات، وأصعب الأسئلة (نسبة الإجابة الخاطئة لكل سؤال).

### المرحلة 4 – الأنشطة الصفية والمحتوى التعليمي والتواصل
**الأنشطة:** `Activities`، `ActivityGroups`، `ActivityGroupMembers`، `ActivitySubmissions`.
- نشاط فردي أو جماعي، توزيع الطلبة على مجموعات (يدوي أو عشوائي)، مواعيد، توثيق بالصور والملفات، تقييم بمعايير (Rubric) بسيطة، إمكانية عرض الأعمال المميزة لبقية الصف.

**المحتوى التعليمي:** `Lessons`، `LessonResources`.
- ترتيب هرمي: المادة ← الوحدة ← الدرس. لكل درس: ملخص، ملفات، روابط، فيديو مضمَّن (YouTube أو ملف)، مع ترتيب وتاريخ نشر.
- تتبع اطلاع الطالب على المحتوى (تم الفتح/الإكمال).

**التواصل:** `Announcements`، `Conversations`، `Messages`.
- إعلانات: من الإدارة للجميع أو من المعلم لشعبه، مع مرفقات وتثبيت.
- رسائل: معلم ↔ طالب، معلم ↔ ولي أمر، إدارة ↔ الجميع. ضوابط من الإعدادات: هل يُسمح للطلبة بمراسلة بعضهم؟ هل يمكن للإدارة الاطلاع على الرسائل؟ ساعات إرسال مسموحة اختيارياً.
- كل الإشعارات المرتبطة عبر خدمة الإشعارات من المرحلة 1.

### المرحلة 5 – الدرجات والتقارير ولوحة الإدارة
- **سجل الدرجات:** رصد درجات الواجبات والاختبارات والأنشطة تلقائياً في `eschool.GradeBook` مع ربطها (إن أمكن) بنظام الدرجات الحالي في SMS عبر إعداد اختياري "ترحيل إلى الدرجات الرسمية" يتحكم به المعلم/الإدارة. أوزان قابلة للضبط لكل نوع.
- **تقرير الطالب:** ملخص أداء لكل مادة، نسبة التسليم في الموعد، متوسط الاختبارات، الاطلاع على المحتوى، رسوم بيانية بسيطة، تصدير PDF.
- **تقرير ولي الأمر:** نفس التقرير لكل ابن، مع إرسال ملخص أسبوعي كإشعار.
- **تقارير المعلم:** حالة الشعبة، الطلبة المتعثرون (تأخر متكرر أو درجات منخفضة)، مقارنة بين الشعب.
- **لوحة الإدارة:** إحصاءات عامة (المعلمون النشطون أسبوعياً، نسب التسليم، معدلات الاختبارات لكل مادة وصف، أكثر الوحدات استخداماً)، تقارير نشاط المعلمين، إدارة الإعدادات، عرض سجل التدقيق.
- **التصدير:** Excel (استخدم المكتبة الموجودة في المشروع، وإلا فـ ClosedXML) وPDF (استخدم المكتبة الموجودة، وإلا اقترح خياراً متوافقاً مع .NET 5 واحصل على موافقتي).

### المرحلة 6 – التجهيز للإطلاق
- مراجعة أمنية شاملة (OWASP Top 10) وتوثيق النتائج.
- تحسين الأداء: فحص الاستعلامات البطيئة، إضافة فهارس، Caching للقوائم الثابتة (المواد، الصفوف).
- مهام مجدولة (Hosted Service): تذكير قبل المواعيد، إغلاق الاختبارات المنتهية، الملخص الأسبوعي لولي الأمر، تنظيف الملفات اليتيمة.
- دليل المستخدم المختصر لكل دور في `docs/eschool/user-guide/` (عربي، مع لقطات شاشة إن أمكن).
- دليل النشر: المتطلبات، الإعدادات، سكربتات الترحيل، النسخ الاحتياطي، الاسترجاع.
