# Module 19 — Fees

**Phase:** 6 — Finance | **Status:** Draft for review | **Rule prefix:** `BR-FEE`

---

## 1. Purpose

Define what students owe: fee categories, per-grade fee structures per academic year, automatic charge generation at registration/re-registration, VAT treatment, pro-ration, miscellaneous charges, late-fee policy, and the student financial position that everything downstream (installments, payments, discounts, statements) reconciles to (BR-GLB-064).

## 2. Scope

**In:** fee category catalog (tuition, transport, books, uniform, registration, activity, exam, copy fees…), fee structures (grade-year price lists), charge (invoice) generation & posting, VAT configuration per category, pro-ration policy (mid-year entry/withdrawal), miscellaneous ad-hoc charges, late-fee policy engine, credit/adjustment notes, opening balances (BR-AYR-009 carry-forward), **payer model** (§3 BR-FEE-004), withdrawal fee settlement.
**Out:** installment scheduling (Module 20), receipt/collection (Module 21), discount rules (Module 22), service-fee *triggers* (transport/store/cafeteria modules request charges through this module's engine).

## 3. Business rules

| ID | Rule |
|----|------|
| BR-FEE-001 | **Fee categories** are cataloged with: bilingual names, VAT treatment (rate ref/exempt per BR-SET Q2 multi-rate decision), refundability class, mandatory/optional, service-linked flag (transport/books/uniform generated by service assignment), GL export mapping code (README Q9 interface). |
| BR-FEE-002 | **Fee structures** = price list per grade-year profile per category (amount, currency BR-GLB-060); year-versioned, approved before year activation (BR-AYR-004 checklist); structure changes after charges exist apply **forward only** (new charges) — posted charges never reprice (BR-GLB-062). |
| BR-FEE-003 | **Charges** (invoices) post per student per category (doc 08 strict series): auto-generated at registration (BR-ADM-007), re-registration (BR-AYR §4), and service assignment (transport route assignment → transport charge; store book-bundle issue → book charge); manual misc charges permission-gated. Posted charges are immutable — corrections via credit/adjustment notes (strict series) with reason + P2 (Finance Manager). |
| BR-FEE-004 | **Payer model:** every charge has a bill-to payer. v1 payers: financially-responsible parent(s) (BR-PAR-005 per-child assignment). The payer is an **abstraction from day one** (`Payer` may be Parent or — activation-flagged — Sponsor entity: company/embassy/charity), so sponsor billing (Gulf reality, Module 11 Q1) activates in v1.x without schema change. Statements, receipts, and dunning follow the payer. |
| BR-FEE-005 | **VAT:** per category treatment snapshot at posting (BR-GLB-061); charge documents show net/VAT/gross per line; **e-invoicing readiness**: charge documents carry the structural fields for country e-invoicing regimes (UUID, hash chain placeholders per ZATCA-style requirements) — activation per country pack (README Q3), design here, implementation gated. |
| BR-FEE-006 | **Pro-ration** (mid-year entry/withdrawal): policy per category (none / monthly / per-term / daily) configured per school; the engine computes and displays the basis on the charge; withdrawal settlement (BR-STU-006 finance clearance) applies the same policy symmetric (refundable portion → Module 21 refund flow, non-refundable per category class). |
| BR-FEE-007 | **Late fees:** policy per school (flat/percentage per overdue installment, grace days, max cap, stop-conditions); computed by scheduled job as **proposed** charges requiring Finance confirmation (batch) before posting — never silently auto-posted; waivable via Module 22 waiver flow (WF-06 family). |
| BR-FEE-008 | **Student financial position** = posted charges − credit notes − discounts (Module 22) − payments/allocations (Module 21), per student and consolidated per payer (BR-PAR-005); computable as-of any date (BR-GLB-064); aged receivables buckets configurable (30/60/90 default). |
| BR-FEE-009 | Opening balances (carry-forward) post as a dedicated charge type referencing the source year (BR-AYR-009 reconciliation hard-check). |
| BR-FEE-010 | All financial documents T1-audited; generation batches logged with totals (BR-AUD system domain); fee structures T1 after approval. |

## 4. Workflow

Fee structure: Draft → Finance Manager review → Principal approve (P3) → locked at year activation. Charge generation: automatic on triggering events (atomic with them, BR-WF-009) or batch (re-registration season) with preview totals → confirm. Misc charge: entry → P2 (Finance Manager) above threshold. Credit note: request → P3 (Finance Manager → Principal per threshold P4). Late-fee run: job proposal → Finance batch confirm.

## 5. User roles

Finance Manager (owner), Cashier (view positions, no structure rights), Registrar (charge triggers via registration), Principal (approvals), Service module operators (trigger service charges), Parent (portal: own charges view), Auditor.

## 7. Database concept

Entities: `FeeCategory`; `FeeStructure` + `FeeStructureLine` (grade-year × category, approved versions); `Charge` (student, payer ref, category, amount net/VAT/gross, source event, status, strict number); `CreditNote`; `LateFeePolicy` + `LateFeeRun` (proposals→posted); `Payer` (abstraction: parent-backed v1, sponsor-ready); `OpeningBalance` (charge subtype). Position/aging are computed views (materialized for dashboards). All amounts decimal per BR-GLB-060; every document snapshots VAT config (BR-GLB-061).

## 8. Required screens

1. Category catalog & VAT mapping.
2. **Fee structure workbench** — grade-year grid (categories × grades), copy-from-last-year with % uplift tool, approval submission, version compare.
3. Charge explorer — filters (student/payer/category/status/source), document view (print bilingual tax-invoice layout).
4. Misc charge entry — student picker, category, reason, threshold routing.
5. Credit note flow — against-charge selection, reason, chain submission.
6. Late-fee run console — proposal list with per-student computation basis, exclude toggles, batch confirm.
7. **Student/payer position** — statement of account (multi-year, as-of date), aging view, drill to documents (shared with Modules 20/21 screens).
8. Portal: fees per child + family consolidated view (payer perspective).

## 9. Validation rules

Structure lines ≥ 0, currency = school currency; no duplicate active structure per grade-year-category; generation preview totals must be confirmed; credit note ≤ remaining charge value; pro-ration basis displayed and stored; late-fee proposals respect grace/cap; misc charges require category + reason; VAT fields mandatory when pack requires e-invoicing structure. |

## 10. Reports

Fee structure book per year (bilingual, parent-publishable) · Charges register per period/category · Expected vs posted revenue per grade (leakage check: enrolled × structure vs charges) · Aged receivables by payer/grade/section (BO-01 core) · Credit note register with reasons · Late-fee register (proposed/posted/waived) · Pro-ration audit report · VAT summary per period (return-preparation feed) · GL export journal summary (README Q9) · Opening-balance reconciliation (BR-AYR-009). |

## 11. Dashboard widgets

Finance Manager: total receivables + aging donut, expected-vs-posted gap, late-fee proposals pending. Principal: revenue posted vs budget year-to-date, receivables trend. Portal (parent): total due + next installment (Module 20 feed).

## 12. Notifications

`InvoicePosted` → payer; `CreditNoteIssued` → payer; `LateFeeApplied` → payer (formal wording per pack, doc 09 Q2); `StructureApproved` → Registrar, Admissions (pricing live); `GenerationBatchCompleted` → Finance (totals); `ExpectedVsPostedGap` (threshold) → Finance Manager (leakage alert). |
